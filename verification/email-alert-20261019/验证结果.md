# 邮件警报接入验证

用户选择：沿用网站原有波动警报，使用 QQ 邮件和手机 QQ 邮箱新邮件通知；本次不配置运营商短信。

已部署到本机 `http://127.0.0.1:8766/`。原规则仍为北京时间当日涨跌幅 ±2.5%，每方向每日一次。

## 验证结果

- Python 邮件模块、监控接入、API 和既有警报回归：123 项通过，见 `backend.log`。
- 邮件 UI：14 项通过；既有终端前端与交互：52 + 17 项通过。合计本轮 206 项检查通过。
- QQ SMTP 465 的 TLS 连接可用，未进行真实 SMTP 授权登录或发送。
- 实际页面验证：配置读取、只读刷新、授权码必填、试发按钮禁用、帮助展开和无横向溢出；浏览器无脚本错误。
- 授权码控件为 password，禁止自动填充；配置使用 Windows 当前用户 DPAPI，公开 API 不返回凭据。
- 修复邮件状态/配置/试发数据库异常导致请求断开的问题，改为脱敏 503，不影响行情读取。
- 增加独立重放线程，短暂队列锁等待后自动恢复近期已持久化的警报；按事件 ID 防重复，测试声音不会自动发邮件。

## 当前实际状态

部署验收时 `configured=false`、`enabled=false`，无排队或发送记录，行情为实时状态。

尚需用户在本机配置页输入 QQ SMTP 授权码、启用并保存，再手动发送测试邮件。真实收件、垃圾邮件分类及手机通知尚未验证；未将模拟发送当成实际送达。
