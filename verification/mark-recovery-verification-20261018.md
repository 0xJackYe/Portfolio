# 标记价 / IV 自动恢复核验

用户问题：BTC-261030-63000-P 的盘口和指数持续更新，但标记价落后一分钟以上，工作台报“标记价/IV已陈旧，仅可查看报价参考”。

根因证据：mark WS 曾连续 SubscriptionTimeout、完整业务帧计数 0；同地址独立公开订阅可正常收到约 218KB 的 mark 数组。原 REST 处理会等待整个快照所有 future，成交统计重试会拖延 mark 提交，任一失败后的全局退避也会阻断补齐。原非压缩目录响应约 1,011,727 字节，本机 gzip 对照为 26,884 字节、完整接收约 0.88 秒。

修复：

- 单飞、最多两请求并发的 mark 专用小响应补齐；优先当前合约，其次策略候选。独立于全快照超时和普通失败退避，继续共用 `get_public` 的请求权重、429/418冷却和有限重试。
- 前端只向本机续约；原字段时效校验继续生效。同步时用温和状态提示，真实字段恢复后自动计算，CSV保留原失效原因。
- 严格核验请求 symbol、价格、IV 和完整 Greeks。失败响应、错合约、缺字段不刷新旧字段时间。并发 WS / REST 更新、同毫秒更新、全快照晚返回均不能回滚较新的数据。
- 公共 REST gzip 有界解压及完整性校验；最近已核验目录原子保存，重启保留原接收时间。

自动回归：`mark-recovery-final-tests-20261018/report.json`，873项全部通过。覆盖原终端、钱包、看板、定价、风险与新增恢复/压缩/目录/HTTP/UI回归。
