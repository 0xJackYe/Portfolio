# 全站测试与优化报告

范围：本机比特币终端的价格警报、期权链、单腿与组合模拟、收益风险、卖 Put 工作台和钱包走势。采用现有全量回归、故障注入、真实 Chrome 页面操作、静态资源检查与部署后公开行情观测。没有实际下单，没有访问已取消授权的私有期权账户，没有改动 Windows 启动或 VPN 配置。

## 修复的实际问题

| 模块 | 触发与影响 | 完成的修复 |
| --- | --- | --- |
| 前端行情合并 | 晚到快照可将新观察的 0.02 张深度回滚到旧的 8 张 | 同时保护四个盘口字段及原始时间；混合观察撤销有效证明并等待核验 |
| 卖 Put 试算记录 | 修改输入后的 120 毫秒防抖期间点击记录，或记录前深度刚失效/合约刚到期 | 点击时立即重新读取、计算和校验；无效结果不写入本机 |
| 风险比较 | 短暂“盘口快照待核验”使已验证的历史参考消失 | 保留完整带时间参考，取消当前有效资格；真实零流动性继续剔除 |
| 到期日分组 | 缓存日期文本可能与官方毫秒时间对应的北京日期不一致 | 统一以官方到期时间分组；日期格式缓存限制 128 项 |
| 重启后响应顺序 | 新进程快照已到达后，旧进程的 HTTP/SSE 回调仍可切回旧实例和目录 | 进入渲染队列前隔离近期退役实例，并保护待渲染版本；退役历史最多 16 项 |
| WS 排序 | 未来事件可污染入口和盘口队列水位，随后正常行情被丢弃 | 两层按交易所校准时钟拦截未来帧；真实本机接收时间不改写 |
| 盘口序列 | 缺少序列号的帧清空已知水位，随后旧序列可以覆盖 | 保留已知序列号，继续拒绝较旧盘口 |
| 恢复状态 | 实时数据已恢复，旧 REST 失败仍显示 recovering | 从当前完整且新鲜的 WS 数据派生 live 状态；原始请求及成功时间保留 |
| 多合约恢复 | 16 合约固定每 8 秒刷新超过自身 80 权重/分钟预算，排后合约反复过期 | 按关注数量调整节奏，优先最旧完整盘口，并保持原预算 |
| 终端初次读取 | 首个 HTTP 或 JSON 读取挂起会阻塞推送和操作 | SSE 独立启动；请求及 JSON 读取有 10 秒总超时；晚到失败不覆盖已恢复行情 |
| 提醒设置 | 保存超时后控件长时间禁用，重复点击可能重复提交 | 超时释放控件、保留输入，明确结果待确认，不自动重复写入 |
| 终端错误恢复 | 格式错误提示残留，或 0/负数价格被标为实时 | 有效推送清除连接错误并保留未保存输入提示；非正价格不标实时 |
| 钱包长时间停留 | 同日停留不会自动同步，失败后无持续恢复 | 可见时每 5 分钟刷新，返回页面补刷新，失败退避并保留有效快照 |
| 钱包缓存与汇率 | 无效日期、乱序及非正汇率可进入缓存；存储受限影响查看 | 严格校验日期、顺序及报价；存储不可用仍可查看、切换并刷新 |

## Chrome 页面验收

在本机真实服务操作并核验：

- 三模块导航及延迟加载，警报记录展开与收起；未修改真实警报阈值或播放测试声音。
- 帮助、到期日、无结果搜索、清除筛选保留日期、Greeks、合约详情、自选加入后恢复原状态。
- 卖 Put 单腿数量 0.1、费用 1、结算价 0 的情景净盈亏、最大盈亏一致；负数量拦截；买卖方向切换。
- 同到期 Call/Put 两腿组合、固定报价、净权利金与两个平衡点；Esc 关闭及结束多选。
- 收益风险方向/类型/排序切换、参数校验、暂停固定快照、导出按钮。CSV 内容及触发由实际控制器回归验证；浏览器下载回执等待超时，因此没有把浏览器文件落盘检查记为通过。
- 专注报价隐藏外层导航，退出后恢复；钱包收起展开、币种 CNY/USD/BTC、30D/全部、盈亏周期、专注余额及 iframe 内 Esc 退出，随后恢复初始选择。
- 更新后的真实终端无捕获到的控制台 error 日志。实际扬声器可听性、桌面通知权限以及 Windows 重启未纳入本轮浏览器验收。

静态资源：生产白名单的 24 个资源全部返回 200、非空、no-store 及 nosniff，记录为 `assets.json`。没有使用跨站权限或安全限制的放宽来让测试通过。
